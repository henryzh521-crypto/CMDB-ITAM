## 交付期修复与复测（2026-10-10）

### 产品缺陷

1. **低库存联动被 Webhook 订阅门控（P0，CT-13 回归发现）**：`WebhookDispatcher` 在「无启用的端点订阅该事件」时提前返回，低库存联动（站内信 / 自动补货单）在门控之后的代码块内随之整体失效——未配置 Webhook 的部署里 `LOW_STOCK_MODE` 形同虚设。修复：`stock.movement` 事件豁免订阅门控，联动只由模式开关决定（无订阅时入队自然空转，仅多一条端点 SELECT，其余事件类型的跳过优化不变）。复测：CT-13 通过（ticket 模式自动建补货单 + 幂等校验）、CL-08 通过（双实例并发出库，全库仅一张补货单）。
2. **SSE 连接表项泄漏**：`SseConnectionRegistry.quietComplete` 只捕获 RuntimeException，客户端半开连接触发的 IO Error 逃逸后连接表项不回收，最终挤占 200 连接 / 实例上限。修复：捕获范围扩大到 Exception，并为 SseEmitter 设 24 小时超时兜底。复测：CC-07 通过（20 路建连 → 断开回收 → 再建连两轮 + 3/3 广播）。
3. **接口限流误伤 SSE 建连**：突发限流按请求数计，SSE 建连易被 429 拒绝。修复：`UserRateLimitFilter` 豁免 SSE 建连路径。复测：CC-07 20 路建连全部成功。
4. **监控总览无缓存全表扫描（PERF-08）**：`countMonitoredAssets` 每请求全表计数、`targetHealth` 逐目标统计。修复：分别加 60s / 30s 缓存，并对相关表 ANALYZE。复测：PERF-08 p50 53 ms → 9 ms（预算 120 ms）。
5. **资产列表深分页 OFFSET 扫描（PERF-02）**：第 4000 页需跳过约 2.8 万行。修复：两段式查询（先按游标定位页内主键，再按主键取行）。复测：p50 38 ms → 27 ms（预算 100 ms）。

### 测试套件缺陷（方法学，非产品问题）

6. **SSE 用例双生成器假超时**：CT-15 / CC-07 / CL-07 原以两个生成器读同一响应，闲置生成器持有的响应对象被 GC 时 urllib3 关闭底层连接，另一生成器读到连接重置表现为超时。修复：单生成器消费全部事件帧。复测：三套件全绿。
7. **UI-07 选择器二义性**：布局铃铛下拉与通知中心页各有一个「全部已读」按钮，Playwright strict mode 报错。修复：选择器限定 `.noti-toolbar` 工具栏。复测：通过。
8. **UI-08 视口不足**：看板 6 列（每列 280px）在 1440 宽视口下「已关闭」列溢出可视区，拖拽 drop 落空。修复：用例视口调整为 1920×900。复测：合法拖拽生效、非法移动回弹并提示，均通过。

### 环境要求明确

9. **CORS_ORIGINS 须包含浏览器实际访问源**：默认白名单仅 `http://localhost:5173`；经反向代理或以其他主机名 / 地址访问而未配置对应 Origin 时，浏览器登录 POST（必带 Origin 头）会被 CorsFilter 以 403 拒绝（curl 不带 Origin 头故不易察觉）。`deploy/.env.example` 已注明按实际访问地址配置。
