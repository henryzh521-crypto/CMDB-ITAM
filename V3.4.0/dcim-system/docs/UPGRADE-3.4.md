# 智算资产管理平台 v3.4.0 升级说明

v3.4.0 以**权限模型补齐、平台防护、多实例部署和测试体系**为主。可从 v3.2.x / v3.3.x 直接升级。
全部改动经 `tests/` 下 80 个自动化用例（9 个套件）在 10 万资产、双实例环境上回归通过。

> 从 v3.2.0 升级的，请先阅读 `docs/UPGRADE-3.3.md` 第一节（v3.2.0 安装包密钥外泄与轮换）。

---

## 一、⚠ 升级前必读：删除权限复位

v3.3 及以前，后端写死「只有管理员能删除」，角色权限矩阵里给非管理员勾选的「删除」**从未生效**。
v3.4 起「删除」改为按角色显式授予，勾选即生效。为了不在升级的瞬间放大权限，迁移 V45 会：

1. 把所有非 ADMIN 角色上已勾选的「删除」复位为不允许；
2. 在操作日志里写一条 `RESET_DELETE_PERM` 记录，列出受影响的「角色:模块」。

升级后请管理员在「系统管理 → 操作日志」按动作 `RESET_DELETE_PERM` 查看名单，到「角色管理 → 编辑 → 删除」列按需重新授予。
在此之前，非管理员的使用体验与 v3.3 相同（不能删除）。

## 二、升级步骤

### Docker 部署

```bash
# 在旧安装目录
./dcimctl backup                                 # 先手工备份一次
./dcimctl upgrade /path/to/dcim-system-3.4.0     # 复制 .env/证书 → 自动备份 → 构建 → 启动
```

- 首次启动执行数据库迁移 V45（秒级）。
- `.env` 会被沿用；新增配置项都有默认值，不改也能运行（见第四节）。
- 安装程序会把 `artifacts/backend/` 中残留的旧版 jar 移到 `artifacts/stale-jars-<时间>/`，避免「覆盖解压后仍跑旧包」（v3.3.1 的根因）。

### 原生部署（systemd）

替换 `artifacts/` 后执行 `./install.sh --native`。启动脚本会在多个 jar 并存时选择**版本号最高**的一个。
如 `/etc/dcim/platform.env` 是自行维护的，可参照 `deploy/native/platform.env.template` 补上第四节的新配置项（不补则用默认值）。

### 升级后自检

```bash
ADMIN_PW='<admin口令>' EXPECT_VERSION=3.4.0 python3 tests/run_all.py -s smoke
```

5 项全部通过即说明运行的是 3.4.0、接口无 5xx、登录与权限链路正常。界面右上角「关于本系统」也会显示前后端版本，不一致时会标红。

### 回滚

V45 只新增一列、复位删除勾选、替换一个视图（列与语义不变），v3.3 后端可在 V45 之后的库上继续运行
（Flyway 默认忽略「未来版本」的迁移）。回滚时换回旧目录即可；复位掉的删除勾选在 v3.3 本来就不生效，无需恢复。

## 三、行为变化（请通知用户）

| 变化 | 说明 |
|---|---|
| 删除改为显式授予 | 见第一节。删除按钮只对有删除权限的用户显示 |
| 工单导出需要「导出」权限 | v3.3 工单导出只校验读权限；现在与资产导出一致，角色未勾选「导出」时返回 403 |
| 接口限流 | 每个登录用户每秒 20 次（突发 40）、匿名每 IP 每秒 10 次（突发 20）、导出 / 导入 / 批量操作每用户每分钟 10 次；超出返回 429 和 `Retry-After`。每 IP 的总闸由每分钟 600 次放宽到 3000 次，NAT 后的多人不再互相挤占 |
| 账号锁定 | 同一账号 15 分钟内跨 IP 累计失败 30 次即锁定 15 分钟（防分布式撞库）；近 30 天在某 IP 登录成功过的，从该 IP 登录不受影响。管理员可在「用户管理」看到「锁定」标记并一键解锁 |
| 字段级权限（新） | 角色可对资产、工单的字段设置「隐藏」或「只读」。隐藏字段不出现在列表、详情、导出、搜索结果中，也不能用于筛选；改动受限字段返回 403。有字段限制的用户不能批量导入。现有角色没有字段规则，升级后行为不变 |
| 多角色合并 | 字段取最宽：任一角色可见即可见；数据范围同样取最宽 |
| 授权上限扩展 | 非管理员授权时，除模块读写外，删除权限、数据范围、字段规则也不能超过自己 |
| 连接池耗尽 | 返回 503 + `Retry-After`，不再返回 500；每实例连接池默认 20 条（原为 10） |
| Webhook | 投递记录与业务数据在同一事务提交：业务回滚则不投递，进程崩溃也不丢事件。新建 / 启用的 Webhook 在其他实例上最迟 5 秒生效 |
| 分类树 | 有资产或物料读权限即可读取分类树（v3.3 需要「分类」模块权限，导致资产页下拉为空） |
| 运营总览 | 没有报表权限的用户看到提示页，不再连续弹出 403 |

## 四、新增配置项（均有默认值）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `RATE_LIMIT_PER_MINUTE` | 3000 | 每 IP 每分钟总闸；0 = 关闭全部限流 |
| `RATE_LIMIT_USER_RPS` / `RATE_LIMIT_USER_BURST` | 20 / 40 | 每用户令牌桶 |
| `RATE_LIMIT_ANON_RPS` / `RATE_LIMIT_ANON_BURST` | 10 / 20 | 未登录请求按 IP 的令牌桶 |
| `RATE_LIMIT_HEAVY_PER_MINUTE` | 10 | 导出 / 导入 / 模板 / 批量操作 |
| `LOGIN_MAX_FAIL_PER_ACCOUNT_GLOBAL` | 30 | 跨 IP 失败多少次锁定账号 |
| `LOGIN_ACCOUNT_LOCK_MINUTES` | 15 | 锁定时长 |
| `LOGIN_TRUSTED_IP_DAYS` | 30 | 登录成功的 IP 被信任多少天 |
| `DB_POOL_MAX` | 20 | 每实例数据库连接上限；多实例时 实例数 × 该值 须小于 PostgreSQL `max_connections`（编排为 200） |
| `DB_POOL_TIMEOUT_MS` | 10000 | 借连接最长等待，超时返回 503 |
| `SECCOMP_OPT` | `seccomp:unconfined` | 仅作用于 postgres、minio 容器；宿主 Docker 较新时建议改为 `no-new-privileges:true` 以启用默认 seccomp |

限流与登录计数都存放在 Redis，多实例之间共享；未配置 Redis 时退化为单实例内存计数。

## 五、新增与改进

- **字段级权限**：角色编辑页新增「字段权限」区，按模块选择隐藏 / 只读字段；后端在统一入口与出口执行（响应剔除并声明 `X-Field-Hidden` 头、请求体比对现值、导出列过滤、搜索谓词排除）
- **接口文档**：登录后访问「接口文档」页面或 `/api/openapi.json`（OpenAPI 3.0，运行时生成），每个接口标注所需权限、字段策略和入参别名；文档不对匿名开放
- **关于本系统**：右上角菜单显示前端与后端版本、构建日期，不一致时提示
- **角色列表搜索**：按编码 / 名称搜索，不区分大小写
- **用户管理**：显示账号锁定状态与剩余时间，可解锁
- **多实例部署**：定时任务锁持有到周期的 90%，跨实例的时钟偏差与执行耗时不再导致同一周期重复执行；`job_lock.run_count` 记录执行次数便于核对
- **性能**：容量页功率聚合改写（10 万资产下约快 25~30%）并缓存 30 秒；审计记录补齐对象号
- **部署加固**：Prometheus 关闭远程生命周期接口（`--web.enable-lifecycle` 可被未授权调用关停），`./dcimctl monitoring reload` 改用 SIGHUP 热加载；仍使用 `latest` 标签的 MinIO 镜像在安装时锁定为已拉取的摘要，避免日后重建时悄悄换版本
