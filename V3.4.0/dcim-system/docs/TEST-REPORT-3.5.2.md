## 一、本版范围

v3.5.2 为 **P3 稳定性与安全加固版**：落地 v3.5.1 回归报告第四节 8 项遗留事项中的 6 项编码修复，2 项经评估维持现状关闭。含 1 个数据库迁移（V47，hw_snapshot 时间索引，已登记校验和）。新增回归用例 CT-17（带外端点并发唯一约束）、CL-09（PAT 吊销跨实例生效），总计 95 个。

## 二、修复与强化清单

### P3-1 定时任务锁租约上限（P0）

1. **续租封顶**：`ClusterJobLock` 心跳续租不可超过「加锁时刻 + 上限」（`dcim.scheduler.cluster-lock.max-lease-seconds`，默认 1800 秒）。持锁实例被强杀或心跳线程失控时，锁至多在上限内自愈释放——v3.5.1 回归中 HealthScoreService 被「已死实例的残留锁」阻塞约 45 分钟的问题不再发生。
2. 上限须大于最慢定时任务的执行时长；`lease-seconds`（600）仍为常规续租步长。

### P3-2 带外端点 bmc_ip 并发去重兜底（P1）

3. **三处 DuplicateKeyException → 409 映射**（端点创建 / 批量导入 / 自动发现上报）：并发创建同一 `bmcIp` 的竞态穿透应用层 check-then-act 后，由数据库唯一约束兜底，映射为 409「端点已存在」而非 500。复测：CT-17 通过（顺序重复 409 + 并发 8 路恰好 1×200 / 7×409，无 500）。

### P3-5 监控栈镜像摘要锁定（P1）

4. **compose 12 处镜像引用变量化**（postgres/redis/tdengine/caddy/prometheus/alertmanager/blackbox/ipmi-exporter/snmp-exporter/grafana/minio 等），`install.sh` 新增 `pin_images()`：安装/升级完成后把实际拉取的 RepoDigest 写入 `.env` 的 `*_IMAGE` 变量，防止 registry 端覆盖 tag 悄悄换版本；已是 `@sha256:` 引用的跳过。升级镜像：删除对应 `*_IMAGE` 行后重新拉取。

### P3-6 可信代理边界收敛（P0）

5. **XFF 信任面收敛**：默认可信代理从全部 RFC1918 收敛为「回环 + `172.16.0.0/12`（Docker 网桥）」。内网客户端直连后端端口时可伪造 `X-Forwarded-For` 冒充任意来源 IP、绕过登录跨 IP 锁定（SE-06）与审计定位的风险关闭。原生部署且网关同处 10/8、192.168/16 网段的需在 `.env` 显式配置 `DCIM_TRUSTED_PROXIES`（新增说明）。
6. **解析算法标准化**：`ClientIp.resolve` 改为标准算法——从 XFF 最右一跳向左跳过可信代理，取第一个非可信地址即真实客户端（伪造的前缀条目天然被忽略；全链可信退回最右一跳）。
7. 同步修复配置缺口：`application.yml` 的宽信任默认值会覆盖代码收敛值，已一并收敛（否则 P3-6 实际不生效）。

### P3-7 PAT 吊销跨实例即时生效（P1）

8. **Redis pub/sub 广播**：吊销 API Token 时本地清缓存并向 `dcim:pat-invalidate` 频道广播，其余实例收到后立即驱逐校验缓存（原多实例吊销窗口最长 60 秒）。未接 Redis 的单实例部署行为不变。复测：CL-09 通过（实例 A 吊销后，已进实例 B 缓存的令牌 0.0 秒内被拒）。

### P3-8 硬件快照保留策略（P1）

9. **SnapshotRetentionJob**：每日 02:40 分批删除超期 `hw_snapshot`（默认 180 天，`dcim.collector.snapshot-retention-days`，≤0 不清理），分批提交避免长事务与锁放大。
10. **V47 迁移**：`hw_snapshot (collected_at)` 索引支撑按时间过滤的删除路径（原 `(endpoint_id, collected_at DESC)` 索引不覆盖）；空表秒建。DP-06 校验 47 个迁移未被改动。

### 评估关闭项

11. **P3-3 Webhook DNS rebinding TOCTOU**：彻底方案需放开 JDK 受限头，评估不采用；维持 v3.5.1 起的三重缓解（JVM DNS 缓存 30s + 投递前紧邻 send 的 URL 守卫二次校验 + https 目标 TLS 主机名校验）。
12. **P3-4 Tomcat 10.1.31 升级**：受 Spring Boot 3.3.x BOM 管理约束，待 BOM 跟进后整体升级（当前 10.1.31，无已知在野漏洞影响本项目）。

## 三、CL-06 等效验证（job_lock 双实例互斥）

CL-06 慢测（SLOW=1，约 3 分钟）未在批量回归中执行，改以 job_lock 快照等效验证：双实例（8081/8082）同时在线，取回归批次后 412 秒窗口（库时间 18:02:38 → 18:09:30）比对各定时任务 `run_count` 增量：

| 任务 | 周期 | Δrun_count | 单实例预期 | 判定 |
|---|---|---|---|---|
| SlaEscalationService.scheduledRun | 60s | 7 | 6~7 | 1x ✓ |
| WebhookDeliveryWorker.tick | 5s | 81 | 82~83 | 1x ✓ |
| InspectionScheduler.tick | 60s | 7 | 6~7 | 1x ✓ |
| AlertScheduler.autoTicket | 60s | 6 | 6~7 | 1x ✓ |
| IpamService.scheduledSync | 300s | 1 | 1 | 1x ✓ |

全部任务增量与单实例执行频率一致、无翻倍——**每周期仅一个实例执行，互斥语义成立**。

说明：HealthScoreService.scheduledRun（周期 1 小时）在窗口内增量为 0：上一持有者为重启前的旧实例（锁定于 17:35:47，租约 600 秒早已自然过期），新实例按 fixedDelay 节奏于下一周期重新竞争——属正常节律，非阻塞。
