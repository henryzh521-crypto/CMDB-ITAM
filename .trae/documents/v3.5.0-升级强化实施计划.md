# DCIM 平台 v3.4.0 → v3.5.0 升级强化实施计划

## Context

用户要求对智算资产管理平台进行「结构、功能、联动等升级强化」，已确认：**四个方向全做**（联动闭环、实时化推送、可视化增强、结构强化）、**版本升为 v3.5.0**、**前后端全栈交付**。平台 v3.4.0 刚完成 18 处缺陷修复与生产级交付（80 项测试通过、部署包已产出），本轮在其基础上叠加新能力。

**硬约束**：
- 后端离线编译（build.sh，javac + GBK @file），**不能新增第三方依赖**；SSE 用 spring-webmvc 自带 SseEmitter，跨实例用已有 spring-data-redis pub/sub
- 双实例集群部署，新联动不得破坏 CL-01~06；性能预算不可回退（PERF 9 项基线）

**已验证的关键事实**：
- Flyway 最新 V45 → 新版用 **V46**；版本号在 `VERSION`、`resources/dcim-build.properties`、`build.sh:6`、`install.sh:25`（回退值）、`package.json`
- 前端无 vuedraggable → 看板拖拽用原生 HTML5 DnD
- `MainLayout.vue` 已有通知铃铛 + 30s 轮询（保留为降级），无独立通知中心页
- `ScheduledJobLockAspect` 无差别拦截所有 `@Scheduled` → **SSE 心跳必须用自建守护线程**（ScheduledExecutorService），否则双实例下另一台心跳失效
- Redis 条件装配（REDIS_HOST 空则无）→ SSE 跨实例需降级单机分发
- ci-relations 已有单源影响/依赖拓扑（CiGraphService.traverse）→ 本轮做**全量拓扑浏览页**
- SLA 升级已发站内信，缺 webhook 事件与 SSE；`notifyOnTransition` 已覆盖提交/通过/驳回/完成，缺「开始处理/关闭」
- EventTypes 目录 + DomainEventCaptureAspect（AOP 捕获）+ WebhookDispatcher（BEFORE_COMMIT 发件箱）为事件基座，28 处调用点不动，新增组合门面

## 方案设计

### A. 联动闭环
1. **盘点差异→工单**：`InventoryTaskController.complete`（L386，applyCountAdjustments 之后）统计 diffCount>0 明细（ASSET 盘亏/盘盈/错位 + MATERIAL 差额），同事务调 `InventoryDiffTicketService.createDiffTicket`（woType=盘点差异，description 附差异清单）；失败回滚 complete（一致性优先）
2. **低库存→预警/补货工单**：`WebhookDispatcher.checkLowStock` 命中时调 `LowStockService.onLowStock`（AFTER_COMMIT 尽力而为，try/catch 不回滚出入库）：按 `dcim.linkage.low-stock.mode=off|notify|ticket` 决定 notifyRole(仓库管理员) / `ActorContext.runAs("admin")` 建补货单（建议量=safety-stock，**幂等**：存在未完结补货单则跳过）
3. **SLA 升级→webhook+SSE**：SlaEscalationService.doRunOnce CAS 成功分支补发 `WORKORDER_SLA_ESCALATED` 领域事件（站内信保留）
4. **工单通知补全**：notifyOnTransition 补「开始处理」（通知 applicant）、「关闭」（通知 applicant+handler）两 case

### B. 实时化推送（SSE）
- `SseConnectionRegistry`：`ConcurrentHashMap<userId:connId, SseEmitter>`，超时 0 自管，上限 200/实例，心跳 = 自建单线程守护 executor（25s `:ping` 注释帧），onCompletion/onTimeout/onError 清理死连接——**禁用 @Scheduled**
- `SsePushService`：pushUser/broadcast；本机直发 + Redis `convertAndSend("dcim:sse", envelope)`；Redis 缺席仅本机
- `RedisSseRelay`：@Conditional(Redis 装配)，订阅 dcim:sse → 本机分发
- `SseController`：`GET /api/notifications/sse?token=`（EventSource 不能带 Authorization 头 → JwtAuthFilter 仅对该路径支持 query token；Caddy 对该路径日志去 query）
- `SseEventRelay`：AFTER_COMMIT + fallbackExecution，把 DomainEvent 转 `workorder`/`alert` 频道 SSE
- `NotificationAdapter.insert` 成功后追加 pushUser → **所有既有站内信自动实时化**

### C. 可视化增强
- `TopologyView.vue`：全量拓扑（ECharts Graph 力导向 + 机房过滤 + 关系图例 + 节点跳转）；后端 `CiRelationController` + `GET /api/ci-relations/graph`（复用 traverse 上限截断防护）
- `WorkorderKanbanBoard.vue`：按状态分列看板，原生 DnD 拖拽调 transition，409 回弹；列表页加表格/看板切换
- `DashboardView.vue`：卡片显隐/排序（localStorage `dcim.dashboard.layout`，布局编辑抽屉勾选+上下移，不做拖拽）

### D. 结构强化
- `UnifiedEventPublisher` 组合门面：`publish(DomainEvent)`（透传 Spring 事件，发件箱语义不变）/ `notify(...)`（站内信+SSE）/ `publishAndNotify(...)`；EventTypes 扩充 `WORKORDER_SLA_ESCALATED`、`INVENTORY_DIFF` 并登记 catalog（webhook 订阅校验依赖 isKnown）
- 报表定时导出**不做**（V44 report_settings 已覆盖参数持久化，定时导出收益不成比例，记入 UPGRADE-3.5.md 说明）

### 配置开关（application.yml `dcim.linkage.*` / `dcim.sse.*`）
inventory-diff-ticket.enabled(默认 true)、low-stock.mode(默认 notify)、low-stock.wo-type(补货)、sse.enabled(true)、sse.max-connections-per-instance(200)、sse.heartbeat-ms(25000)。零新表。

## 测试计划（新增用例）
- CT-11~14（contract）：新事件入 catalog；盘点盘亏生成差异工单明细正确；低库存 OUT→补货单且重复触发不重复；SLA 升级产生 webhook 投递

- PERF-21（performance）：SSE 开启 + 20 活跃连接下资产列表 p50≤60ms
- UI-07~09（e2e）：通知中心红点/toast/已读/跳转；看板拖拽+409 回弹；拓扑渲染+图例过滤
- CL-07/08（cluster）：Redis pub/sub 跨实例 3s 内送达；双实例出库补货单仅一张（幂等）
- SSE 服务端用 python requests stream 逐行断言帧

## 风险与回退
1. **心跳被集群锁拦截**（最高）：自建守护线程，评审确认 registry 无 @Scheduled
2. **SSE 耗尽 fd**：200/实例上限 + 心跳清理 + 超限 503 → 前端降级轮询（代码保留）
3. **token 进 URL**：Caddy 日志去 query；文档注明内网权衡
4. **联动建单失败**：盘点差异单同事务回滚；低库存单 AFTER_COMMIT 尽力而为（WARN 不阻断）
5. **性能回退**：新监听为内存操作/单次 Redis publish，PERF-21 守护
6. **整体回退**：`dcim.sse.enabled=false` + `dcim.linkage.*` 全关即回到 3.4.0 行为；V46 仅 INSERT 行无破坏性 DDL
